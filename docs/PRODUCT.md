# Product Specification

## 1. Overview

Stella Atlas는 사용자의 위치와 날짜를 기반으로 날씨와 천문 정보를 분석하여  
별 관측 가능 여부와 최적 관측 시간을 안내하는 웹 서비스입니다.

---

## 2. Problem Definition

천체관측 초보자는 관측 여부를 판단하기 위해 여러 정보를 따로 확인해야 합니다.

- 일반 날씨
- 시간대별 구름량
- 습도와 가시거리
- 일몰 시각
- 박명 종료 시각
- 달의 위상
- 월출 및 월몰
- 관측 대상의 위치

그러나 각 수치가 실제 관측에 어떤 의미인지 이해하기 어렵습니다.

Stella Atlas는 흩어진 정보를 하나의 관측 판단으로 변환합니다.

---

## 3. Product Goals

### Goal 1

사용자가 10초 이내에 오늘 관측 가능 여부를 판단할 수 있게 합니다.

### Goal 2

관측하기 좋은 시간대를 시간 단위로 제공합니다.

### Goal 3

관측 점수의 근거를 사용자가 이해할 수 있게 설명합니다.

### Goal 4

초보자가 천체관측에 진입하는 장벽을 낮춥니다.

### Goal 5

향후 관측 기록과 개인화 추천으로 확장 가능한 기반을 만듭니다.

---

## 4. Success Metrics

초기에는 아래 지표를 관찰합니다.

- 관측 조건 조회 완료율
- 위치 입력 후 결과 화면 도달률
- 재방문율
- 저장한 관측 장소 수
- 추천 시간 상세 보기 비율
- 관측 결과 기록 비율
- 오류 발생률
- 외부 API 실패율
- 평균 API 응답 시간

초기 단계에서는 허영 지표보다 사용자 행동을 우선합니다.

---

## 5. Personas

### Persona A — 관심은 있지만 지식이 부족한 사용자

- 별을 보고 싶지만 어디서 무엇을 확인해야 하는지 모릅니다.
- 전문 용어에 익숙하지 않습니다.
- 단순한 “좋음/보통/나쁨” 판단을 원합니다.

### Persona B — 주말 관측을 계획하는 사용자

- 차로 외곽 관측지로 이동합니다.
- 장소별 조건을 비교하고 싶습니다.
- 관측 최적 시간과 달 밝기를 중요하게 봅니다.

### Persona C — 입문 장비 사용자

- 쌍안경 또는 소형 망원경을 사용합니다.
- 오늘 볼 수 있는 쉬운 대상을 추천받고 싶습니다.
- 관측 기록을 남기고 싶어 합니다.

## 6. Primary User Journey

```text
서비스 접속
  ↓
현재 위치 허용 또는 지역 검색
  ↓
날짜 선택
  ↓
오늘의 종합 관측 상태 확인
  ↓
시간대별 점수 확인
  ↓
최적 관측 시간과 이유 확인
  ↓
선택적으로 관측 장소 저장
```

## 7. MVP Functional Requirements

### FR-001 위치 입력

사용자는 다음 방식으로 위치를 입력할 수 있어야 합니다.

- 브라우저 현재 위치
- 지역명 검색
- 지도 또는 좌표 입력은 후속 기능으로 고려

### FR-002 날짜 선택

- 기본값은 사용자 로컬 날짜
- MVP는 단기 예보 범위 내 날짜만 지원
- 지원 범위를 벗어난 날짜는 명확히 안내

### FR-003 시간대별 날씨 조회

각 시간대에 대해 다음 정보를 제공합니다.

- 기온
- 구름량
- 강수 확률
- 습도
- 가시거리
- 풍속

### FR-004 천문 정보 조회

- 일몰 시각
- 박명 종료 시각
- 월출 및 월몰
- 달의 위상
- 달의 조도 또는 밝기 비율

### FR-005 관측 점수

각 시간대에 0~100 점수를 제공합니다.

점수는 최소한 다음 요소를 고려합니다.

- 구름량
- 강수 가능성
- 가시거리
- 습도
- 풍속
- 달 밝기
- 박명 상태

### FR-006 결과 설명

점수와 함께 다음을 제공합니다.

- 좋은 조건
- 불리한 조건
- 가장 큰 감점 원인
- 초보자를 위한 짧은 안내

### FR-007 최적 시간 추천

해당 날짜에 관측하기 가장 좋은 시간 구간을 추천합니다.

추천 가능한 시간이 없으면 이유를 설명합니다.

### MVP Backend API Strategy

MVP의 핵심 공개 API는 `GET /api/v1/observations`입니다.

이 API가 위치와 날짜를 기준으로 날씨, 천문 정보, 시간대별 점수와 최적 관측
시간을 하나의 사용자 중심 결과로 제공합니다. 날씨와 천문 공급자 연동은 내부
구현으로 유지하며 공급자별 API를 공개하지 않습니다.

지역명 검색은 핵심 조회를 지원하는 별도 API로 설계하되 공급자와 응답 계약이
확정되는 마일스톤에서 구체화합니다. 즐겨찾기 장소, 최근 조회 위치와 서버 관측
기록 API는 실제 OAuth 사용자 연결을 완료하는 Milestone 8 범위입니다.

### Milestone 8 Functional Requirements

#### FR-010 계정 위치 라이브러리

- 로그인 사용자는 이름을 붙인 즐겨찾기 위치를 저장·조회·삭제할 수 있습니다.
- 관측 조회 위치는 사용자가 체크한 경우에만 최근 위치에 저장합니다.
- 최근 위치 좌표는 소수점 이하 4자리로 축소하고 사용자별 최신 10개만 유지합니다.
- 홈과 밤하늘 시뮬레이터에서 즐겨찾기와 최근 위치를 다시 선택할 수 있습니다.
- 모든 위치 목록과 삭제는 현재 내부 사용자 UUID의 소유권 범위로 제한합니다.

#### FR-011 서버 관측 메타데이터

- 로그인 사용자는 관측 시각, IANA timezone, 선택 좌표, 최대 500자 코멘트와
  해시태그를 계정에 생성·조회·삭제할 수 있습니다.
- 사진, EXIF 원본과 로컬 IndexedDB 식별자는 서버로 전송하지 않습니다.
- 다른 사용자의 기록 존재 여부를 노출하지 않도록 ID와 owner를 함께 조회합니다.
- 서버 미디어와 로컬 게시물 이전은 저장·검사·마이그레이션 정책 승인 전까지
  제공하지 않습니다.

### Milestone 7 Functional Requirements

#### FR-008 로컬 관측 게시물

- 사용자는 이미지 파일을 선택하거나 지원 기기의 카메라로 촬영할 수 있습니다.
- 로컬 MVP는 게시물당 이미지 한 장, 최대 20MB를 지원합니다.
- 이미지에 EXIF 촬영 시각과 GPS 좌표가 있으면 입력 초깃값으로 사용합니다.
- 메타데이터가 없거나 읽을 수 없으면 값을 추정하지 않고 비워 둡니다.
- 사용자는 자동 입력된 촬영 위치와 시각을 언제든 수정할 수 있습니다.
- 게시물은 사진, 위도·경도, 시간대를 포함한 촬영 일시, 짧은 코멘트와
  해시태그를 포함할 수 있습니다.
- 코멘트 원문은 보존하고 해시태그는 검색 가능한 별도 값으로 파싱합니다.
- Milestone 7에서는 게시물과 이미지가 현재 브라우저 프로필의 IndexedDB에만
  저장되며 서버로 전송되지 않습니다.
- 사용자는 로컬 게시물을 조회, 수정하고 삭제할 수 있습니다.

#### FR-009 대화형 천체 관측 시뮬레이션

- 사용자는 좌표와 관측 시각을 기준으로 밤하늘을 탐색할 수 있습니다.
- 시간 이동, 방향 전환, 확대·축소와 주요 천체·별자리 표시를 제공합니다.
- 시뮬레이터는 브라우저 위치를 사용할 때 명시적인 권한을 요청하고 직접 입력도
  지원합니다.
- Canvas 또는 엔진 초기화 실패 시 빈 화면 대신 지원 안내를 표시합니다.
- 플라네타리움 엔진은 교체 가능한 프런트엔드 adapter로 격리합니다.

### Milestone 7 Constraints

- 웹 카메라는 보안 컨텍스트와 사용자 권한이 필요하며 권한 거부를 정상 상태로
  처리합니다.
- 카메라 캡처 결과에 원본 EXIF가 항상 포함된다고 가정하지 않습니다. 촬영 직후
  현재 시각이나 브라우저 위치를 제안할 수 있지만 출처를 표시하고 사용자의
  확인·수정을 거칩니다.
- 브라우저 저장소는 용량 제한, 사용자 삭제, 시크릿 모드와 기기 변경으로
  사라질 수 있으므로 영구 백업으로 표현하지 않습니다.
- 정확한 GPS 좌표는 민감 정보이며 저장 전 사용자에게 보여 주고 수정·삭제할 수
  있게 합니다.

## 8. Non-Functional Requirements

### Performance

- 핵심 API의 정상 응답 목표는 2초 이내
- 외부 API 호출은 타임아웃 필수
- 동일 위치와 시간 범위 데이터는 적절히 캐싱

### Reliability

- 외부 API 장애를 내부 서버 장애와 구분
- 일부 데이터가 없을 때 가능한 범위에서 결과 제공
- 필수 데이터가 부족하면 점수를 생성하지 않고 명확히 안내

### Accessibility

- 색상만으로 상태를 표현하지 않음
- 키보드 탐색 지원
- 적절한 명도 대비
- 스크린 리더가 이해 가능한 레이블

### Privacy

- 현재 위치는 사용자 동의 후 사용
- 정확한 위치 저장은 선택 사항
- 위치 로그 최소화
- 계정 없이도 핵심 조회 가능

## 9. Observation Score Concept

초기 점수는 규칙 기반으로 구현합니다.

### Example Factors

| Factor | Meaning | Example Impact |
|---|---|---:|
| Cloud Cover | 하늘을 가리는 정도 | 매우 큼 |
| Precipitation | 관측 불가능 가능성 | 매우 큼 |
| Visibility | 대기 투명도 간접 지표 | 큼 |
| Humidity | 이슬과 투명도에 영향 | 중간 |
| Wind | 장비 안정성과 체감 환경 | 중간 |
| Moon Brightness | 어두운 천체 관측 방해 | 중간 |
| Twilight | 충분히 어두운지 여부 | 큼 |

점수 공식은 사용자에게 설명 가능한 구조를 유지해야 합니다.

## 10. Result States

### Excellent

- 매우 좋은 관측 조건
- 적극 추천

### Good

- 관측 가능
- 일부 조건 주의

### Fair

- 밝은 천체 중심 관측 권장

### Poor

- 제한적인 관측 가능성
- 큰 감점 원인 표시

### Not Recommended

- 강수, 짙은 구름, 박명 등으로 관측 비추천

등급 경계는 데이터와 사용자 피드백을 기반으로 조정합니다.

## 11. Edge Cases

- 위치 권한 거부
- 지역 검색 결과 없음
- 극단적인 위도
- 일몰이 없거나 해가 지지 않는 날짜
- 월출 또는 월몰이 없는 날짜
- 외부 API 일부 실패
- 누락된 가시거리
- 타임존이 다른 장소 조회
- 자정을 넘는 관측 추천
- 일광절약시간 적용 지역
