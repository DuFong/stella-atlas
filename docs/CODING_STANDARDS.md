# Coding Standards

이 문서는 일상적인 구현 규칙을 요약합니다. 충돌이 있을 때는 `AGENTS.md`가
우선합니다.

## General

- 요청을 만족하는 가장 작은 일관된 변경을 만듭니다.
- 기능 중심 구조와 `api → application → domain` 의존 방향을 지킵니다.
- 도메인은 가능한 한 프레임워크에 의존하지 않게 유지합니다.
- 외부 공급자 DTO, JPA Entity와 공개 API DTO를 분리합니다.
- 시간대와 단위를 타입과 이름으로 명시합니다.
- 비밀값, 토큰과 정확한 사용자 위치를 로그나 저장소에 남기지 않습니다.
- 새 의존성은 필요성, 유지보수 상태, 라이선스와 비용을 검토합니다.

## Java and Spring

- Java 21을 사용하고 명확성을 높일 때 record와 최신 문법을 활용합니다.
- 생성자 주입만 사용하고 필드 주입과 변경 가능한 정적 상태를 피합니다.
- Controller는 HTTP 처리, 검증과 매핑만 담당합니다.
- Application Service는 유스케이스 조율과 트랜잭션 경계를 담당합니다.
- Domain은 비즈니스 규칙과 유효한 상태를 보장합니다.
- 외부 호출에는 연결 및 응답 타임아웃을 설정합니다.
- 서버 기본 타임존에 의존하지 않습니다.

## TypeScript and Next.js

- TypeScript strict mode를 유지하고 `any`를 피합니다.
- Server Component를 기본으로 사용하되 브라우저 상호작용이 필요할 때만
  Client Component를 사용합니다.
- 서버 데이터, UI 상태, 데이터 조회와 표현을 분리합니다.
- API 접근을 중앙화하고 응답의 런타임 검증을 고려합니다.
- 모바일 우선, 접근 가능한 HTML과 키보드 탐색을 적용합니다.
- 로딩, 빈 상태와 오류 상태를 구현합니다.

## Tests

- 테스트 이름은 행동과 기대 결과를 설명해야 합니다.
- 순수 도메인 로직은 빠른 단위 테스트를 우선합니다.
- Spring Context는 통합 동작이 필요한 테스트에서만 로드합니다.
- 외부 API는 실제로 호출하지 않고 경계와 응답 변환을 검증합니다.
- 관측 점수, 시간대 변환, 입력 검증, 예외 매핑과 Repository Adapter를
  필수 검증 대상으로 봅니다.

## Formatting and Files

- `.editorconfig`와 기존 모듈 설정을 따릅니다.
- 파일은 UTF-8과 LF 줄바꿈을 사용합니다.
- 무관한 포맷 변경과 대규모 파일 이동을 섞지 않습니다.
- Flyway 마이그레이션은 병합된 파일을 수정하지 않고 새 버전을 추가합니다.

## Verification

변경 영역에 실제로 존재하는 테스트, 린트, 타입 검사와 빌드 명령을
실행합니다. 실행하지 못하거나 실패한 검증은 결과 보고에 명확히 기록합니다.
