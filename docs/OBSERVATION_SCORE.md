# Observation Score

## Status

관측 점수는 **Milestone 5 — Observation Score**에서 구현합니다. 이 문서는
구현 전 지켜야 할 계약과 결정이 필요한 항목을 기록하며, 현재 가중치나
임계값을 확정하지 않습니다.

## Purpose

관측 점수는 특정 위치와 시간의 날씨·천문 조건을 사용자가 빠르게 이해할 수
있는 결과로 변환합니다. 점수만 제공하지 않고 추천 여부, 등급과 이유를 함께
반환해야 합니다.

## Contract

- 점수 범위는 0~100이며 최소값과 최대값을 항상 보장합니다.
- 동일한 입력은 동일한 결과를 반환합니다.
- 각 시간대에 독립적으로 점수를 계산할 수 있어야 합니다.
- 모든 주요 가점과 감점에는 안정적인 코드, 영향도와 사용자 메시지가
  있어야 합니다.
- 알 수 없는 필수 데이터를 임의의 정상값으로 간주하지 않습니다.
- 외부 API DTO나 Controller DTO를 점수 정책에 전달하지 않습니다.
- 하나의 거대한 조건문 대신 독립적인 규칙이나 정책을 조합합니다.

예상 결과 형태:

```json
{
  "score": 82,
  "grade": "GOOD",
  "recommended": true,
  "reasons": [
    {
      "code": "LOW_CLOUD_COVER",
      "impact": 8,
      "message": "구름이 적어 관측에 유리합니다."
    }
  ]
}
```

## Candidate Factors

- 구름량
- 강수량 또는 강수 확률
- 습도
- 가시거리
- 풍속
- 달의 조도와 고도
- 박명 상태
- 대기 투명도와 시상(데이터가 신뢰할 수 있을 때)

## Decisions Required Before Implementation

- 초기 기준 점수와 요인별 가중치
- 등급 경계와 `recommended` 기준
- 즉시 관측 불가로 판단할 조건
- 누락 데이터 처리와 점수 생성 중단 기준
- 양의 영향도와 음의 영향도의 표현 방식
- 사용자 메시지의 언어 및 현지화 정책

각 결정을 데이터 출처와 제품 근거와 함께 기록하고, 중요한 변경은
`docs/DECISIONS.md`에 ADR로 남깁니다.

## Required Tests

- 각 독립 규칙의 경계값
- 0과 100 범위 고정
- 동일 입력의 결정성
- 여러 규칙 조합
- 누락되거나 예상 밖인 공급자 값
- 등급과 추천 경계
- 이유 코드, 영향도와 메시지

가중치나 임계값을 변경할 때 이 문서와 관련 테스트를 함께 수정합니다.
